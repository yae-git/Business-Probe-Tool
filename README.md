# 业务探活工具 (Business Probe Tool) v2.3

> 保障业务连续性的可视化连通性探测工具 —— 及时发现因网络设备故障、配置错误导致的业务中断，支撑网络整改。

---

## 📌 工具定位

本工具用于**业务连通性探测**，核心价值：

- **事前识别**：单次探测识别当前在用的业务系统（URL 探测模块）
- **事中监控**：24 小时实时探活，业务中断立即告警（探活任务 / Ping 模块）
- **事后取证**：完整日志记录探测结果，支撑向客户汇报与网络整改

---

## ✨ 核心特性

| 特性 | 说明 |
|------|------|
| **零依赖** | 纯 Python 标准库（tkinter + http.client），无需 `pip install` |
| **四模块架构** | URL 业务探测 / 探活任务管理 / Ping 探活 / 告警设置 |
| **业务区分组** | 按网络区域（互联网 / 政务网 / 政务外网…）分类管理 URL |
| **多任务并行** | 可创建多个独立探活任务，各自配置间隔 / 超时 / 状态码判定 |
| **状态码自定义** | 支持「业务探测」（要求精确状态码）与「网络连通探测」（能通即可）两种模式 |
| **强制 ASCII 探测引擎** | 自研 `_force_ascii()` + curl 兜底，彻底消灭 latin-1 编码错误 |
| **声音 + 弹窗告警** | winsound 蜂鸣三连 / 自定义 wav / 强制弹窗（可配置提示语模板） |
| **数据持久化** | 所有配置自动保存为 JSON，下次打开自动恢复 |
| **导入 / 导出** | 一键导入成功 URL 到探活任务；导出 TXT 报告 / CSV 清单 |

## 🔧 环境要求

- **操作系统**：Windows 10+（声音告警依赖 `winsound`；curl 兜底依赖系统自带 `curl.exe`）
- **Python**：3.7+（推荐 3.10+）
- **依赖**：无需安装任何第三方包

> 注：非 Windows 环境可运行探测逻辑，但声音告警会静默（仅写日志），不影响探测本身。

## 🖥️ 四大模块详解

### 🌐 Tab 1 — URL 业务探测（单次识别工具，**不告警**）

> 这是**前置业务识别**模块：手动或批量导入 URL，单次探测识别哪些业务「在用」、哪些「停用」。仅记录结果，**不触发声音/弹窗告警**（它不是 7×24 监控）。

**功能：**
- 📥 **导入 TXT**：一键导入 `urls.txt` 格式清单（每行一个 URL，`#` 开头为注释）
- ➕ **手动添加**：逐个录入业务地址
- 🔄 **重新探测**：清空当前所有探测结果 + 数据重置后，重新执行全部探测
- ▶ **全部探测** / **快速探测选中**：批量或选中探测
- 🏷️ **业务区管理**：顶部下拉切换业务区；支持新建 / 重命名 / 删除；右键菜单「移动到其他业务区」
- ✓ / ✗ **分类标记**：右键菜单标记「在用」「停用」，自动过滤
- 📤 **导入成功 URL 到探活任务**：将当前业务区探测成功的 URL 一键创建为 24h 实时探活任务
- 💾 **导出**：TXT 报告（含按区分组 + 汇总统计）/ CSV（成功清单 / 失败清单，utf-8-sig BOM 兼容 Excel）

---

### 📋 Tab 2 — 探活任务管理（核心 24h 监控模块）

> 这里创建的任务会**持续循环探测**，业务中断时触发声音 + 弹窗告警。

**功能：**
- ➕ **新建任务**：命名任务，独立配置 URL 列表 / 间隔 / 超时 / 重试 / 状态码
- 🔀 **探测模式**：
  - **业务探测**：要求返回指定状态码（如仅认 200）才算正常
  - **网络连通探测**：只要能连上（200/301/302/502 等）就算通，忽略业务层状态码
- 🎯 **状态码自定义**：逗号分隔，如 `200,201,301,302`
- ▶ / ⏹ **启动 / 停止**：单独启停某个任务，或一键全部停止
- 📜 **实时日志**：每个任务独立日志面板，显示每轮探测时间戳 / URL / 状态码 / 结果

---

### 📡 Tab 3 — Ping 探活

> 对网络设备（非 HTTP 服务）做 ICMP 连通性监控。

**功能：**
- 📝 **设备列表**：记录设备名称 + IP / 主机名 + 备注
- 🔁 **周期性 Ping**：设置间隔后自动循环 ping 所有设备
- ▶ **单次 Ping**：选中设备手动测试一次
- 🔔 **离线告警**：Ping 不通同样触发弹窗 + 声音

---

### 🔔 Tab 4 — 告警设置

> 全局告警配置，对探活任务（Tab2）和 Ping 探活（Tab3）生效；**URL 业务探测（Tab1）不触发告警**。

- **弹窗标题**：自定义告警窗口标题
- **提示语模板**：支持变量替换
  - `{url}` — 失败的业务地址
  - `{task}` — 任务名称
  - `{result}` — 探测结果（状态码 / 错误原因）
  - `{time}` — 触发时间
- **声音文件**：浏览选择 `.wav` 文件；不选则用系统蜂鸣三连
- **测试按钮**：
  - 「测试声音」— 仅播放告警音
  - 「测试完整告警」— 弹窗 + 声音一起触发

## 📝 URL 清单格式（urls.txt）

```
# 这是注释行，会被忽略
https://yxsy.dag.shenyang.gov.cn:8090/AUP/usingPlat.jsp
http://cjrlb.mzj.shenyang.gov.cn/#/login
https://www.hbqlsy.cn/cms

# 空行也会被忽略
```

- 每行一个 URL
- `#` 开头为注释
- 支持 HTTP / HTTPS，支持带端口、带 `#` hash 路由的地址
- 中文字符、特殊字符均会自动做 percent-encoding（无需手动处理）

## 🔬 探测引擎说明（v2.3 关键修复）

### 为什么需要专门处理 URL 编码？

Python 标准库 `urllib.request` 内部**硬编码了 latin-1 编码**，当 URL 中包含中文或非 ASCII 字符时，会抛出：

```
'latin-1' codec can't encode characters in position X-Y
```

传统 `_encode_url()` 做 percent-encoding 仍无法完全绕过（urllib 内部二次编码），表现为**所有 URL 全军覆没报编码错误**。

### v2.3 的解决方案

```
探测请求
   │
   ├─ 策略1: http.client (强制 ASCII 清洗)
   │     └─ _force_ascii() 对 host / path / 每个 header 值强制转纯 ASCII
   │
   └─ 策略2: 系统 curl 兜底 (自动降级)
         └─ UnicodeEncodeError 时调用系统 curl.exe，完全绕开 Python 编码栈
```

**验证结果**（用户 22 个真实 URL）：

| 指标 | 结果 |
|------|------|
| latin-1 错误 | **0 个** ✅ |
| 探测成功（200/301/302） | 9 个 |
| 探测失败（真实网络问题） | 13 个（DNS 不通 / SSL 证书 / 超时 / 端口拒绝） |

> 失败的 13 个不是 bug，是**真的连不上** —— 这正是工具要发现的问题。

## ❓ 常见问题 / 故障排除

**Q：为什么有些 URL 显示「网络错误」而不是成功？**
A：那是因为当前网络确实访问不到该地址（DNS 解析失败、目标服务器宕机、防火墙拦截等）。这是探测工具的正確行为，说明该业务当前不可用，需要网络整改。

**Q：探测结果显示 SSL 错误怎么办？**
A：目标站点使用了自签名证书或证书链不完整。`http.client` 默认严格校验证书。如需忽略证书错误，可在 `probe_url()` 中把 `ssl.create_default_context()` 改为 `ssl._create_unverified_context()`（不推荐生产环境）。

**Q：Ping 探活在云服务器上没反应？**
A：部分云环境禁用了 ICMP 协议（Ping），会导致所有设备显示离线。这种情况下建议改用 Tab2 的 HTTP 探活。

**Q：配置文件在哪？会不会泄露？**
A：保存在程序同目录的 `.probe_config/` 文件夹，纯本地 JSON，不上传任何服务器。

**Q：可以做开机自启 7×24 监控吗？**
A：可以。建议：
1. 用 `pythonw business_probe_gui.py` 无窗口后台运行（不弹命令行）
2. 或用 Windows 任务计划程序注册为开机自启任务
3. 或直接用早期 CLI 版 `connectivity_probe.py` 搭配任务计划程序
